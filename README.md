# Мост Telegram и Max с Эрой (service desk)

Два бота, которые связывают групповые чаты с клиентами и service desk в Эре:

- **Telegram-бот** (`era_bot/`, запуск `python main.py`);
- **Max-бот** (`max_bot/`, запуск `python main_max.py`).

Боты читают сообщения в группах, где состоят, и пересылают их в микросервис Эры (`MessengersHistoryAPI_ADD`) вместе с вложениями. Ответ оператора из Эры уходит обратно в чат через встроенный HTTP relay (`POST /send`).

## Структура

```
era_bot/               Telegram-бот и общий код
  bot.py               сборка приложения и запуск polling
  handlers.py          обработка сообщений в группах
  admin.py             команды в личке и уведомления о новых чатах
  era_client.py        клиент наносервиса Эры и отправка логов
  outbound.py          HTTP relay для ответов оператора
  subscribers.py       хранение списка подписчиков рассылки
  config.py            настройки из .env
max_bot/               Max-бот (использует era_client и subscribers из era_bot)
  api.py               клиент Max Bot API
deploy/chat-search/    скрипт и стили поиска по чату в интерфейсе Эры
main.py, main_max.py   точки входа
```

## Возможности

- Пересылка текста, фото и документов (включая картинки, отправленные файлом) в `MessengersHistoryAPI_ADD`.
- Обработка миграции группы в супергруппу (смена `chat_id`) через `MessengersHistoryAPI_MIGRATE` (только Telegram).
- Привязка чата к контрагенту Smart командой `@имя_бота Имя Контрагента` прямо в группе (`MessengersHistoryAPI_CREATECHAT`).
- Отправка ответов оператора из Эры в чат через relay `POST /send`.
- Уведомление подписчиков, когда бота добавили в новый групповой чат.
- Рабочие логи уходят в `smart_log.LogService` Эры.
- SOCKS5/HTTP-прокси для доступа к Telegram Bot API.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

В `.env` заполнить как минимум `ERA_ENDPOINT`, `ERA_SECRET`, `OUTBOUND_SECRET` и токен нужного бота (`BOT_TOKEN` или `MAX_BOT_TOKEN`).

## Запуск

Локально:

```bash
python main.py       # Telegram
python main_max.py   # Max
```

В Docker (оба бота сразу):

```bash
docker compose up -d --build
```

Сервисы `bot` (Telegram, relay на порту 8091) и `max_bot` (Max, relay на порту 8090) собираются из одного образа и берут настройки из `.env`. Списки подписчиков и состояние Max-бота хранятся в общем томе `bot_data` (`/app/data`). Внешние порты relay можно переопределить через `TG_OUTBOUND_PORT` и `OUTBOUND_PORT`.

## Конфигурация (`.env`)

Общие:

| Переменная         | Обязательна | Назначение |
|--------------------|-------------|------------|
| `ERA_ENDPOINT`     | да          | URL микросервиса Эры, например `.../rest/v1/domain/nservices/smart_test.HolderService` |
| `ERA_SECRET`       | да          | токен, передаётся как `Authorization: Bearer <ERA_SECRET>` |
| `ERA_LOG_ENDPOINT` | нет         | URL `smart_log.LogService`; по умолчанию берётся с того же сервера, что `ERA_ENDPOINT` |
| `OUTBOUND_SECRET`  | да, для relay | токен, с которым Эра вызывает relay (`Authorization: Bearer <OUTBOUND_SECRET>`); без него relay отклоняет все запросы |

Telegram:

| Переменная           | Обязательна | Назначение |
|----------------------|-------------|------------|
| `BOT_TOKEN`          | да          | токен Telegram-бота |
| `ADMIN_ID`           | нет         | Telegram id администратора, которому доступны команды рассылки |
| `SUBSCRIBERS_FILE`   | нет         | файл со списком id для рассылки, по умолчанию `subscribers.json` |
| `TELEGRAM_PROXY_URL` | нет         | прокси для `api.telegram.org`, например `socks5://user:pass@host:1080` или `http://host:8080` |
| `OUTBOUND_PORT`      | нет         | порт relay, по умолчанию `8091` |

Max:

| Переменная             | Обязательна | Назначение |
|------------------------|-------------|------------|
| `MAX_BOT_TOKEN`        | да          | токен Max-бота |
| `MAX_API_URL`          | нет         | адрес Max Bot API, по умолчанию `https://platform-api2.max.ru` |
| `MAX_CA_BUNDLE`        | нет         | путь к PEM с корневым сертификатом Минцифры |
| `MAX_ADMIN_ID`         | нет         | Max `user_id` администратора; без него команды рассылки отключены |
| `ERA_MAX_CHAT_TYPE`    | нет         | `api_code` Max в справочнике `MessengerTypes` Эры, по умолчанию `max` |
| `MAX_SUBSCRIBERS_FILE` | нет         | по умолчанию `max_subscribers.json` |
| `MAX_STATE_FILE`       | нет         | файл с маркером long polling, по умолчанию `max_state.json` |
| `MAX_FILE_SIZE_MB`     | нет         | лимит размера вложения, по умолчанию `20` |
| `OUTBOUND_PORT`        | нет         | порт relay, по умолчанию `8090` |

## Настройка Telegram-бота

1. Создать бота в BotFather, получить `BOT_TOKEN`.
2. Отключить privacy mode: `/mybots`, выбрать бота, `Bot Settings`, `Group Privacy`, `Turn off`. Либо сделать бота администратором в каждой группе.
3. По желанию задать список команд через `/setcommands`:
   ```
   add_subscriber - Добавить id в рассылку о новых чатах
   remove_subscriber - Удалить id из рассылки
   list_subscribers - Показать список id в рассылке
   ```
4. Добавить бота в группы с клиентами.
5. В каждой новой группе один раз написать `@имя_бота Имя Контрагента из Smart`. Без привязки `MessengersHistoryAPI_ADD` отвечает `404 chat not found`.

## Настройка Max-бота

1. Получить токен в кабинете Max для бизнеса (ботов могут создавать только верифицированные юрлица РФ) и указать его в `MAX_BOT_TOKEN`.
2. Добавить бота в группу клиента и сделать его администратором, иначе Max не присылает боту события из группы.
3. В группе один раз написать `@имя_бота Имя Контрагента из Smart`.
4. Проверить, что в справочнике `MessengerTypes` Эры есть тип с `api_code` = `max` (или задать другой через `ERA_MAX_CHAT_TYPE`).

Домен `platform-api2.max.ru` выпущен на сертификате Минцифры: корневой сертификат должен быть в системе или указан в `MAX_CA_BUNDLE`. Как временный вариант можно указать старый домен `MAX_API_URL=https://platform-api.max.ru`.

## Команды в личке с ботом

| Команда                    | Кто может     | Действие |
|----------------------------|---------------|----------|
| `/start`                   | любой         | бот отвечает вашим id |
| `/add_subscriber <id>`     | администратор | добавить id в рассылку о новых чатах |
| `/remove_subscriber <id>`  | администратор | убрать id из рассылки |
| `/list_subscribers`        | администратор | показать список id |

Администратор задаётся через `ADMIN_ID` (Telegram) и `MAX_ADMIN_ID` (Max), у каждого бота свой список подписчиков. Подписчик должен сам хотя бы раз написать боту (например `/start`), иначе бот не сможет отправить ему уведомление.

## Привязка чата к контрагенту

Сообщение в группе, которое начинается с упоминания бота (`@имя_бота Имя Контрагента`), не пересылается как обычное. Бот вызывает `MessengersHistoryAPI_CREATECHAT` с этим именем и `chat_id` группы и пишет в тот же чат результат: успех или текст ошибки от Эры.

## Что пересылается

Telegram:

- текст (`text` или `caption`);
- фото (самый большой размер);
- документы, включая картинки, отправленные файлом;
- `migrate_to_chat_id` отдельным вызовом `MessengersHistoryAPI_MIGRATE`.

Каждое фото из альбома уходит отдельным вызовом `ADD`.

Max:

- текст, картинки (`image`) и файлы (`file`);
- если в сообщении несколько вложений, каждое уходит отдельным `ADD`, текст передаётся только с первым;
- в качестве `message_id` передаётся `body.seq`.

## Что игнорируется

- личные сообщения боту (кроме команд);
- голосовые, аудио, видеосообщения, стикеры, опросы и служебные сообщения без текста;
- файлы больше 20 МБ: вместо файла в Эру уходит текст с пометкой `[файл >20МБ пропущен]` (в Max лимит настраивается через `MAX_FILE_SIZE_MB`).

## Ответы оператора (relay)

Каждый бот поднимает HTTP-сервер, который Эра вызывает, когда оператор отправляет ответ клиенту из чата.

```
POST /send
Authorization: Bearer <OUTBOUND_SECRET>
Content-Type: application/json

{"chat_type": "telegram", "chat_id": "-1001234567890", "text": "Текст ответа"}
```

- Токен задаётся в `.env` через `OUTBOUND_SECRET` и должен совпадать с тем, который Эра передаёт в заголовке `Authorization`. Если переменная не задана, relay отвечает `401` на любой запрос. Оба бота используют одно и то же значение.
- Telegram-бот принимает только `chat_type = telegram`, Max-бот только `max`.
- Ответы: `200 {"ok": true}`, `400` при неверном теле или чужом `chat_type`, `401` при неверном токене, `502` если мессенджер не принял сообщение.

## Поиск по чату в Эре

`deploy/chat-search/script.js` и `style.css` добавляют в чат-виджет Эры кнопку поиска по сообщениям: фильтр по тексту и автору с подсветкой совпадений. Поиск идёт только по сообщениям, уже загруженным на экран. Файлы подключаются глобально в приложении Эры.

## Логирование

Рабочие события (отправка сообщений, ошибки Эры, сбои рассылки) пишутся через `smart_log.LogService.CreateLogMessage`, см. `send_log` в [era_bot/era_client.py](era_bot/era_client.py). В консоль выводятся только сообщения уровня `WARNING` и выше.
